# translations

A copy of the Firefox Translations models WM Keyboard's on-device translator
(Mozilla's Bergamot engine) runs. The app downloads them from Mozilla's own
server first and from here when that fails. The offline build's **Get the
files** sheet links here, because Mozilla's server answers any browser whose
user agent names Chrome (Chrome itself and every browser built on it) with
HTTP 406, while GitHub serves every browser.

The files are not in this repository's tree. They are assets of the
[`translations` release](https://github.com/wasi-master/wmkeyboard-data/releases/tag/translations),
named `<sha256>-<name>.zst`, for example
`4e7256a9…87-vocab.aren.spm.zst`. That digest is the SHA-256 of the file as
published, still zstd-packed as Mozilla serves it.

- **Unchanged.** Each file is the exact file on
  `firefox-settings-attachments.cdn.mozilla.net` that Mozilla's Remote Settings
  collection `translations-models-v2` points at. Nothing is repacked.
- **Pinned.** Every app build carries the size and SHA-256 of each file, packed
  and unpacked (`BergamotCatalog.kt` in the app repository, generated by
  `native/bergamot-jni/catalog.py`), and refuses a file that does not match. This
  release is only a place to fetch the bytes from.
- **Never replaced.** A newer model has a new digest, so it is a new file. Old
  files stay for the app versions that still pin them.

## Updating

After the app re-pins its catalogue, run the **Mirror Firefox Translations
models** workflow (`.github/workflows/mirror-translations.yml`) from the Actions
tab, which copies Mozilla's files into the release from GitHub's side in a few
minutes. The same script runs locally too:

    scripts/mirror_translations.py --catalog <path to BergamotCatalog.kt>

With no `--catalog` it reads the catalogue from the app repository's `main`
branch. It downloads each missing file from Mozilla, checks its size and
SHA-256 against the pin, uploads it, and skips the files already here, so a run
that stopped part-way can simply be started again. `--dry-run` lists what is
missing. It needs Python 3.9 or later and a signed-in `gh` CLI.
